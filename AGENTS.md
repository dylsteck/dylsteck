# AGENTS.md

This is the repo for [dylansteck.com](https://dylansteck.com) — Dylan Steck's personal site. Read this file before making changes.

## Stack

- [Vite 8](https://vite.dev/) + [TanStack Start](https://tanstack.com/start) + [TanStack Router](https://tanstack.com/router) for routing, SSR, and server routes.
- [Cloudflare Workers](https://developers.cloudflare.com/workers/) as the primary runtime via [`@cloudflare/vite-plugin`](https://developers.cloudflare.com/workers/vite-plugin/) + [Wrangler](https://developers.cloudflare.com/workers/wrangler/).
- [Nitro](https://nitro.build/) is still used for the optional Docker/Node image (`DEPLOY_TARGET=node`, produced as `.output/server/`).
- [React 19](https://react.dev/) + [Tailwind CSS 4](https://tailwindcss.com/) for the UI (via `@tailwindcss/vite`).
- [next-mdx-remote](https://github.com/hashicorp/next-mdx-remote) for MDX blog post rendering (despite the name, used framework-agnostically — we call `serialize()` on the server and `<MDXRemote>` on the client).
- [cf-workers-og](https://github.com/kvnang/cf-workers-og) for dynamic OG images (Workers-compatible `ImageResponse`).
- [@farcaster/miniapp-sdk](https://miniapps.farcaster.xyz) — the site is a Farcaster Mini App.
- [react-three/fiber](https://r3f.docs.pmnd.rs/) + [drei](https://drei.docs.pmnd.rs/) for the homepage's 3D "DS" logo.
- [Bun](https://bun.sh/) is the package manager (`packageManager` in `package.json`). Use `bun install` / `bun add`, never npm.

## Architecture

```
app/
  routes/                         ← file-based routes (pages + server/API routes)
    __root.tsx                    ← HTML shell + global <head>
    index.tsx                     ← /
    info.tsx, apps.tsx, feed.tsx  ← /info, /apps, /feed
    blog.$id.tsx                  ← /blog/:id
    video.$id.tsx                 ← /video/:id
    articles.$id.tsx              ← /articles/:id (client redirect to /blog)
    blog.index.tsx, video.index.tsx ← legacy /blog and /video → /feed 301 redirects
    404.tsx                       ← not-found route
    rss.tsx                       ← /rss (XML server handler)
    sitemap[.]xml.ts              ← /sitemap.xml
    robots[.]txt.ts               ← /robots.txt
    llms[.]txt.ts, llms-full[.]txt.ts  ← /llms.txt, /llms-full.txt
    [.]well-known.farcaster[.]json.ts  ← /.well-known/farcaster.json
    api.feed.ts, api.feed.farcaster.ts ← /api/feed, /api/feed/farcaster
    api.og.blog.$id.tsx           ← /api/og/blog/:id (dynamic OG PNG)
    api.blog.$id.markdown.ts      ← /api/blog/:id/markdown
  router.tsx                      ← createRouter (scrollRestoration, preload intent)
  start.ts                        ← createStart() global request middleware (Accept: text/markdown rewrite for /blog/:id)
  routeTree.gen.ts                ← auto-generated by tanstack-router plugin (gitignored)
  components/                     ← shared components (mdx, topbar, feed-filter, cast, tweet, 3D icons, etc.)
  blog/posts/*.md                 ← blog post source of truth (frontmatter + MD + MDX components)
  blog/utils.ts                   ← blog loader (`import.meta.glob` bundles markdown at build time)
  video/videos.ts                 ← video list
  apps/apps.ts                    ← apps list
  lib/                            ← constants, site metadata, feed utils, feed types
  hooks/                          ← useIsMobile, useFeed, etc.
  global.css                      ← Tailwind import + all custom CSS
public/                           ← static assets (fonts, images, GLB model, favicon)
vite.config.ts                    ← Vite + tanstackStart + tailwind + cloudflare (or nitro when DEPLOY_TARGET=node)
wrangler.jsonc                    ← Cloudflare Workers config
tsconfig.json                     ← bundler module resolution, ES2022, path aliases `app/*` + `#/*`
Dockerfile                        ← optional self-host image (Bun deps → Node/Nitro build → Node runtime)
```

### Key conventions

- **File-based routes**: dots in filenames denote URL segments; literal dots/brackets in URLs are escaped with `[.]`. Dynamic params use `$id`. Server-only routes have a `server: { handlers: { GET, POST, ... } }` property and no `component`.
- **Metadata / SEO**: Every page route sets `head: () => ({ meta, links, scripts })` — duplicate static metadata lives in `__root.tsx`, page-specific metadata lives on each route. Both `fc:frame` and `fc:miniapp` Farcaster embeds are emitted via `createMiniAppEmbed()` in `app/lib/site.ts`.
- **Navigation**: Use `<Link to="/path" params={{ id }} />` from `@tanstack/react-router`, not `<a>`, for internal links. Use `useNavigate`, `useLocation`, `useSearch` — not window.history or URL parsing.
- **Search params**: Typed `validateSearch` on the route defines the shape; `useSearch({ strict: false })` on consumers.
- **Server functions**: Use `createServerFn({ method: 'GET' }).inputValidator(v).handler(fn)` for server-only logic that a loader / client needs. Do not use `fs` / `path` / `process.cwd()` — Workers have no disk. Bundle static content with `import.meta.glob` (see `app/blog/utils.ts`).
- **Images**: Use `app/components/image.tsx` (plain `<img>` with the same `fill` / `sizes` / `priority` / `width` / `height` prop shape that Next's `next/image` had).
- **MDX**: Blog posts use Tweet / Cast / Gallery components mapped in `app/components/mdx.tsx`. Cast component imports from `react-farcaster-embed/dist/client` (the client component build, not the package root which is RSC-only). Tweet uses `react-tweet`'s client `<Tweet>` component. On Cloudflare, `<MDXRemote>` is client-only (`ClientOnly`) because Workers forbid `new Function()`.
- **CSS**: Tailwind 4 via `@tailwindcss/vite`. No `postcss.config.js`. All custom CSS lives in `app/global.css`, imported from `__root.tsx` via `?url`.
- **Fonts**: Geist loaded from Google Fonts (Geist + Geist Mono); do not use the `geist` npm package (Next-only).
- **Blog markdown content-negotiation**: Middleware in `app/start.ts` intercepts `GET /blog/:id` with `Accept: text/markdown` (or `text/x-markdown`, `application/markdown`) and returns processed markdown directly without going through the HTML page.

### Things to avoid

- Do not re-introduce `next`, `next/*` imports, or `'use client'` directives.
- Do not commit `app/routeTree.gen.ts` (auto-generated, gitignored).
- Do not add `postcss.config.js` — Tailwind 4 is wired through its Vite plugin.
- Do not read the filesystem at runtime (`fs`, `process.cwd()`). Workers have no disk; Docker should not depend on copying source markdown either. Use `import.meta.glob`.
- If adding packages that bundle their own Buffer / Node polyfills (like `@farcaster/miniapp-sdk`), add them to `noExternal` in `vite.config.ts` so SSR doesn't try to use Node's builtin `buffer` module.
- Do not use npm (`npm install`, `npm add`, `npx`). Install and add packages with Bun. Use `bunx wrangler` for Wrangler.

## Development

```sh
bun install                      # react-farcaster-embed declares an old React peer range; Bun is fine with it
bun run dev                      # vite + workerd on :3000 (Cloudflare local runtime)
bun run build                    # Cloudflare Workers build (default)
bun run preview                  # vite preview in workerd
bun run deploy                   # build + wrangler deploy
bun run build:node               # Nitro Node build for the Docker image
bun run start                    # node .output/server/index.mjs (after build:node)
```

## Testing requirements

Before considering work complete:

1. **Vite build must pass**: `bun run build` (Cloudflare target) finishes successfully. For Docker/Nitro changes, also run `bun run build:node` and confirm `.output/` is produced. Do not use `bun run build:node` under Bun if you then run the Nitro output under Node — the Dockerfile still builds with `node node_modules/vite/bin/vite.js build` after `DEPLOY_TARGET=node`.
2. **For any non-trivial change**: Run `bun run dev` and verify the affected routes in Chrome. Manually click through the CUJs that touch your change (topbar nav, feed filters, blog post render, etc.).
3. **For anything that changes the Cloudflare runtime, wrangler config, or Worker-sensitive deps:** `bun run build` plus a local `vite preview` / `wrangler dev` smoke test of page routes, JSON APIs, OG images, and markdown content-negotiation.
4. **For anything that changes the Docker/Nitro path:** validate the Docker image. See the next section.

### Validating the Docker image

The `Dockerfile` is the optional self-host path. Some past regressions would have been caught only here (e.g. `bun run build` causing nitro to bundle `Bun.serve()` which then crashes under Node).

You can build & run it from the repo root. If the sandbox doesn't have Docker pre-installed:

```sh
sudo apt-get update && sudo apt-get install -y docker.io
sudo dockerd --iptables=false --bridge=none > /tmp/dockerd.log 2>&1 &
sleep 6
sudo docker info | grep "Server Version"         # confirm the daemon is up
```

Then build and run:

```sh
cd /workspace
sudo docker build --network host -t dylsteck-test .
sudo docker run -d --network host --name dylsteck-run -e PORT=3100 dylsteck-test
sleep 5
```

Smoke-test every category of route (page route, static server route, JSON API, dynamic OG, markdown content-negotiation):

```sh
for p in / /feed /rss /robots.txt /sitemap.xml /llms.txt /.well-known/farcaster.json \
         /apps /info /blog/2025-recap /blog/agentic-workspaces /api/feed; do
  printf "%-40s " "$p"
  curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:3100$p"
done
curl -s -H "Accept: text/markdown" -o /dev/null \
  -w "/blog/2025-recap (md): %{content_type} %{http_code}\n" \
  "http://localhost:3100/blog/2025-recap"
curl -s -H "Accept: application/json" -o /dev/null \
  -w "/api/feed (json): %{content_type} %{http_code}\n" \
  "http://localhost:3100/api/feed"
```

All routes should return `200`. `/blog/2025-recap (md)` must return `text/markdown; charset=utf-8`. `/api/feed (json)` must return `application/json`.

If anything is `500`, inspect the container logs:

```sh
sudo docker logs dylsteck-run | tail -50
```

Typical real issues surfaced via this test:

- `ReferenceError: Bun is not defined` — nitro bundled Bun-only APIs because the Node image build ran under Bun. The Dockerfile does `bun install` only, then `DEPLOY_TARGET=node node node_modules/vite/bin/vite.js build`.
- Missing Node polyfills for packages that ship Buffer / process inline — add the package to `resolve.noExternal` + `ssr.noExternal` in `vite.config.ts`.

Cleanup when done:

```sh
sudo docker stop dylsteck-run && sudo docker rm dylsteck-run
```

## Code style

- TypeScript, but `strict: false` / `strictNullChecks: true`. Prefer explicit types on public APIs; infer inside functions.
- Tailwind utility classes over CSS modules. Keep custom CSS in `app/global.css`.
- Route handlers return native `Response` objects.
- Don't narrate with obvious comments. Explain non-obvious intent only.

## Git

- Work on a `cursor/<descriptive-name>-0175` branch off `main`. Don't commit to `main` directly.
- One commit per logical change. Descriptive messages.
- Don't commit `node_modules/`, `.output/`, `app/routeTree.gen.ts`, or any other generated / installed artifacts (`.gitignore` already handles these).
